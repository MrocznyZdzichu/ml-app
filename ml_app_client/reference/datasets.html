Client module

Datasets

Register sources, stream CSV or Parquet files, manage concrete-version metadata, and explore immutable histories through bounded catalog contracts.

A Dataset is one immutable version. Content, family identity, and version number never change. Metadata merging is the only mutable REST operation; upload a new version when the data changes.

What is a Dataset?

A family has a logical_id; every concrete version has a unique id. Pipelines and governed mappings pin concrete versions for reproducible lineage. Dataset-to-Business-Case mappings live in Dataset Attachments.

Registered source

Metadata for an external file, database, or API source; registration creates a family.

Uploaded source

A local CSV or Parquet stream stored as an immutable file-backed version.

Version history

Default exploration uses bounded pages rather than an unbounded catalog.

Safe transfer

Files stream from disk; previews are bounded to 50,000 rows.

Dataset CRUD

create_dataset, upload_dataset, and the create path of ensure_dataset first search only the authenticated user's visible catalog. If an exact name already exists (case-insensitive), they raise ConflictError; pass force=True to deliberately create another family. A Dataset the user cannot view is neither returned nor disclosed, and therefore does not block creation. Version uploads that supply logical_id are unaffected.
create_dataset(...)Register a non-uploaded source as a new family.

Returns Dataset; registration stores source metadata and does not upload content.

  • name — required source name.
  • source_type — required: file, database, or api.
  • format, description, location_uri, tags, metadata — optional source metadata.
  • database or api — optional descriptor matching the source type.
remote = client.create_dataset(name="Warehouse orders", source_type="database", format="parquet", database=connection)
upload_dataset(...)Stream a local CSV or Parquet file as version 1.

Returns a ready file-backed Dataset. Supplying logical_id creates the next version instead of a new family.

  • file_path — required existing local .csv or .parquet path.
  • name — optional new-family name; inferred from filename when omitted.
  • description, tags — optional version metadata.
  • logical_id — optional existing family ID; requires editor access.
orders = client.upload_dataset("orders.csv", name="orders", tags=["source"])
get_dataset(...)Read one concrete version.

Typed results retain mapping compatibility.

  • dataset — required Dataset ID or Dataset.
dataset = client.get_dataset("dataset-version-id")
update_dataset_metadata(...)Merge metadata into one version.

This is the only mutable Dataset operation; it never changes content, name, family, or version number.

  • dataset — required Dataset ID or Dataset.
  • metadata — required mapping merged into existing metadata.
dataset = client.update_dataset_metadata(dataset, metadata={"retention": "90d"})
delete_dataset(...)Soft-delete one concrete version.

Requires dataset-owner authorization. It preserves lineage and does not delete sibling versions.

  • dataset — required Dataset ID or Dataset.
deleted = client.delete_dataset(dataset)
ensure_dataset(...)Reuse a Business Case-attached Dataset or upload and attach it once.

This conservative convenience workflow never creates an implicit new version for an existing Dataset family.

  • file_path — required local CSV or Parquet file when creation is needed.
  • business_case_name, dataset_name, role — required attachment coordinates.
  • description, tags — optional Dataset metadata.
  • context_note, primary_key_column, target_column — optional Dataset Attachment context.
dataset, created = client.ensure_dataset("orders.parquet", business_case_name="Customer churn", dataset_name="Orders", role="training")

This is a client-side convenience workflow; it composes Dataset and Dataset Attachment endpoints.

Version management

create_dataset_version(...)Upload the next immutable file-backed version.

Resolves the family from an existing version and streams the supplied file without downloading the current Dataset.

  • file_path — required existing CSV or Parquet path.
  • dataset — required Dataset ID or Dataset from the target family.
  • description, tags — optional new-version metadata.
next_version = client.create_dataset_version("orders-2026-08.csv", dataset)
upload_dataset_version(...)Upload the next version of a Business Case-attached Dataset by name.

Compatibility helper that resolves the attached family, then streams one new immutable version. Prefer create_dataset_version when you already have the Dataset.

  • file_path — required existing .csv or .parquet file.
  • business_case_name, dataset_name — required attached Dataset coordinates.
  • description, tags — optional version metadata.
version = client.upload_dataset_version("orders-next.parquet", business_case_name="Customer churn", dataset_name="Orders")

This is a client-side resolver and upload workflow; it has no separate endpoint.

Cataloging

page_datasets(...)Search the visible Dataset catalog in a bounded page.

Returns CatalogPage[Dataset] with the exact filtered total. Use the same filters as the Data UI when comparing results.

  • limit, offset — pagination controls; defaults 30 and 0.
  • search, business_case_id, status, source_type, asset_kind — optional scope filters.
  • pipeline_id, pipeline_type — optional pipeline-origin filters.
  • uploaded_only — excludes views, pipeline outputs, and platform-generated assets.
  • owned_only — restricts results to the authenticated user’s datasets.
  • include_deleted, families — history and grouping controls.
page = client.page_datasets(search="orders", asset_kind="dataset", uploaded_only=True, families=True, limit=30)
page_dataset_versions(...)Read a Dataset family version catalog in one bounded page.

Returns CatalogPage[Dataset] with exact total and continuation metadata.

  • logical_dataset_id — required family ID.
  • limit, offset — pagination controls; defaults 20 and 0.
history = client.page_dataset_versions(dataset.logical_id, limit=20)
iter_dataset_versions(...)Explicitly traverse the complete version catalog.

Uses bounded pages internally. Use it only when every selected version is intended.

  • logical_dataset_id — required family ID.
  • page_size — records per API page, 1 to 100; default 100.
for version in client.iter_dataset_versions(dataset.logical_id): print(version.version_number)
list_dataset_versions(...)Legacy full list of one family’s readable versions.

Materializes the entire version catalog. Prefer page_dataset_versions for interactive use.

  • logical_dataset_id — required Dataset family ID.
versions = client.list_dataset_versions(dataset.logical_id)
list_datasets(...)Legacy full list of readable concrete versions.

Materializes every visible version. Prefer page_datasets for catalogs and use this only when the full selected set is intentional.

  • include_deleted — optional; include soft-deleted history, default false.
datasets = client.list_datasets()
list_dataset_summaries(...)List lightweight dataset fields without preview payloads.

Returns summary metadata for compatible legacy workflows; use the bounded catalog for interactive discovery.

  • include_deleted — optional; include soft-deleted history, default false.
summaries = client.list_dataset_summaries()
dataset_by_name(...)Resolve one Business Case-attached Dataset by exact name.

Searches bounded attachment and version pages, returning the newest version of the unambiguous attached family.

  • business_case_name — required Business Case name.
  • dataset_name — required exact attached Dataset name.
dataset = client.dataset_by_name(business_case_name="Customer churn", dataset_name="Orders")

This is a client-side resolver; it has no separate endpoint.

Inspection

preview_dataset(...)Return a bounded display preview.

The response reports the full row count and the display rows returned.

  • dataset_id — required concrete version ID.
  • limit — display rows from 1 to 50,000; default 20.
preview = client.preview_dataset(dataset.id, limit=20)
download_dataset(...)Stream a complete authorized file to disk.

Writes a partial file and replaces the destination only after the stream succeeds.

  • dataset_id — required concrete version ID.
  • destination — required output path.
  • chunk_size — positive stream block size; default 1 MiB.
path = client.download_dataset(dataset.id, "exports/orders.parquet")

Readable metadata

present_dataset_metadata(...)Build a structured Dataset metadata view.

Separates the version summary, column schema, and remaining structured metadata instead of flattening nested mappings.

  • dataset — required Dataset ID or Dataset.
view = client.present_dataset_metadata(dataset)

This is a client-side presentation method; it has no separate endpoint.

display_dataset_metadata(...)Render structured Dataset metadata in a notebook or terminal.

In Jupyter it renders summary and column tables with collapsed JSON for remaining metadata. In a terminal it prints the same hierarchy as readable text.

  • dataset — required Dataset ID or Dataset.
client.display_dataset_metadata(dataset)

This is a client-side presentation method; it has no separate endpoint.

Errors

HTTP failures map to AuthenticationError (401), AuthorizationError (403), ResourceNotFoundError (404), and ConflictError (409). Missing local paths raise FileNotFoundError; invalid local limits raise ValueError.
