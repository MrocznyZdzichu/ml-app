Client module

Dataset Attachments

Manage role-specific mappings from an exact immutable Dataset version to a Business Case. This is the only client module responsible for those mappings.

An attachment pins a concrete Dataset version. Updating an attachment can change its role and context only; it cannot replace the version. Deleting it removes only the mapping, never the Dataset or lineage.

What is a Dataset Attachment?

An attachment makes data part of a governed Business Case without copying it. It carries the business role and optional key or target-column context needed by downstream pipelines and monitoring.

Version pin

data_asset_id always identifies one immutable Dataset version.

Business context

business_case_id scopes the mapping to a governed ML initiative.

Data role

role declares why that exact version is used in the initiative.

Bounded discovery

Pages filter mappings server-side; iterate only when a full selected range is intended.

Mapping CRUD

create_dataset_attachment(...)Bind a Dataset version to a Business Case.

Returns a typed DatasetAttachment. The caller needs permission to attach the selected readable Dataset to the Business Case.

  • business_case — required Business Case ID or BusinessCase.
  • dataset — required concrete Dataset ID or Dataset.
  • role — required data role from the accepted-values table.
  • context_note, primary_key_column, target_column — optional mapping context.
attachment = client.create_dataset_attachment(case, dataset, role="training", primary_key_column="customer_id", target_column="churned")
get_dataset_attachment(...)Resolve one mapping by ID.

The REST API has no standalone mapping-detail route yet, so the client resolves through bounded pages.

  • business_case — required Business Case ID or BusinessCase containing the mapping.
  • attachment_id — required attachment ID.
attachment = client.get_dataset_attachment(case, "attachment-id")
update_dataset_attachment(...)Update mapping context without retargeting data.

The attached Dataset version cannot change. Only role and optional context are editable.

  • business_case — required Business Case ID or BusinessCase.
  • attachment — required attachment ID or DatasetAttachment.
  • role, context_note, primary_key_column, target_column — optional supported changes only.
attachment = client.update_dataset_attachment(case, attachment, context_note="Validated training population.")
delete_dataset_attachment(...)Remove only the Business Case mapping.

The Dataset, its other mappings, and its lineage remain intact.

  • business_case — required Business Case ID or BusinessCase.
  • attachment — required attachment ID or DatasetAttachment.
client.delete_dataset_attachment(case, attachment)

Discovery

page_dataset_attachments(...)Search one Business Case's mappings in a bounded page.

Returns CatalogPage[DatasetAttachment] with exact filtered total.

  • business_case — required Business Case ID or BusinessCase.
  • limit, offset — bounded pagination controls; defaults 30 and 0.
  • search, role, pipeline_id, pipeline_type — optional server-side filters.
  • uploaded_only, deleted_only — optional history filters.
page = client.page_dataset_attachments(case, role="training", limit=30)
find_dataset_attachment(...)Resolve exactly one mapping for a Dataset version.

Raises ResourceNotFoundError when nothing matches and ResourceAmbiguousError when the Dataset has multiple matching mappings.

  • business_case — required Business Case ID or BusinessCase.
  • dataset — required Dataset ID or Dataset.
  • role — optional exact role filter.
training = client.find_dataset_attachment(case, dataset, role="training")
iter_dataset_attachments(...)Explicitly traverse all selected mapping pages.

list_dataset_attachments is the legacy unbounded equivalent; use either only when loading the entire selected result is intentional.

  • business_case — required Business Case ID or BusinessCase.
  • search, role — optional selected filters.
  • page_size — records per API page, from 1 to 100; default 100.
for item in client.iter_dataset_attachments(case, role="source"): print(item.data_asset_id)

Errors

HTTP failures map to AuthenticationError (401), AuthorizationError (403), ResourceNotFoundError (404), and ConflictError (409). Local exact-resolution ambiguity raises ResourceAmbiguousError.
