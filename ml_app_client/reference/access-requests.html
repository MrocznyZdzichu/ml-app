Client module

Access Requests

Discover the minimal Business Case directory, submit auditable access requests, and process caller-scoped request queues. Typed results retain mapping compatibility: both request.id and request["id"] work.

Directory entries intentionally expose minimal metadata only. Queues are bounded by default: use limit and offset, never a client-side organization-wide list.

What are Access Requests?

A user can request access to a Business Case. Its owner or manager can then approve the request and grant a role, or reject it.

Accepted values

Discovery and submission

page_business_case_catalog(...)Search the minimal organization-wide directory.

Returns a bounded CatalogPage[BusinessCaseCatalogEntry] without exposing inaccessible Business Case details.

  • limit — number of entries requested; integer from 1 to 100, default 30.
  • offset — zero-based number of matching entries to skip; integer ≥ 0, default 0.
  • search — optional text filter of up to 200 characters; default "".
directory = client.page_business_case_catalog(search="churn", limit=30)
request_business_case_access(...)Ask for an auditable role grant.

Submits an access request to the case owner and managers.

  • business_case — Business Case ID or BusinessCase.
  • requested_role — defaults to reader. Allowed: report_viewer, reader, contributor, manager. owner is rejected; ownership uses transfer.
  • justification — required nonblank explanation, from 1 to 2,000 characters. Example: "I maintain the monthly churn report.".
request = client.request_business_case_access("bc_123", justification="Monthly reporting")

Request queues

page_business_case_access_requests(...)Read incoming or submitted requests.

Returns a bounded page scoped to the authenticated caller. The current queue defaults to pending; completed-history boxes leave status unrestricted unless supplied.

  • box — incoming (default), mine, submitted_history, or handled.
  • status — optional pending, approved, or rejected.
  • limit — integer from 1 to 100, default 30.
  • offset — zero-based number of entries to skip, default 0.
incoming = client.page_business_case_access_requests(box="incoming")
page_business_case_access_requests_for_business_case(...)Read one manageable case’s request page.

Pages open requests or decision history for a Business Case the caller can manage.

  • business_case — Business Case ID or BusinessCase.
  • history — False (default) returns pending requests; True selects decision history.
  • status, limit, offset — optional status filter and bounded pagination controls.
page = client.page_business_case_access_requests_for_business_case(case)

Decisions

approve_business_case_access_request(...)Approve and grant a role atomically.

Approves one pending request through the platform authorization workflow.

  • request_id — ID of a pending access request.
  • access_role — allowed: report_viewer, reader, contributor, manager. The role cannot exceed the approver’s effective role.
  • decision_note — optional recorded explanation, up to 2,000 characters.
client.approve_business_case_access_request(request.id, access_role="reader")
reject_business_case_access_request(...)Reject one pending request.

Records a rejection without granting Business Case access.

  • request_id — ID of a pending access request.
  • decision_note — optional recorded explanation, up to 2,000 characters.
client.reject_business_case_access_request(request.id, decision_note="Not required")

Errors

HTTP failures map to AuthenticationError (401), AuthorizationError (403), ResourceNotFoundError (404), and ConflictError (409).
