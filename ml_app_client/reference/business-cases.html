Client module

Business Cases

The central context for datasets, pipelines, models, and their lineage. Models are typed, but retain mapping compatibility: both case.id and case["id"] work.

Pages are bounded by default. Use iter_* only when the full selected range is intended. Normal client workflows archive Business Cases; permanent cascade deletion is intentionally root-only REST maintenance and is not exposed by the client.

What is a Business Case?

A Business Case is the governed workspace that gives an ML initiative its business purpose, access boundary, and lineage. It is required for pipelines, model versions, scoring, serving, and monitoring. Data and analysis can exist independently, then be attached to one or more Business Cases when they become part of a use case.

Business context

Stores the goal, owner, problem type, target column, success criteria, and primary metric that make a model outcome interpretable.

Access boundary

Controls who can view reports, read data, contribute, manage access, or own the workspace. A platform administrator has an audited global bypass.

Lineage anchor

Connects immutable dataset versions, pipeline runs, model versions, predictions, reports, services, and monitoring results to one business purpose.

Not a disposable folder

Normal lifecycle is draft → active/production → archived. Archiving preserves historical results and does not delete governed artifacts.

Artifacts that can belong to a Business Case

Business Case lineage records immutable platform artifacts. Dataset and Data View attachments provide source context; pipeline and serving workflows create the remaining records.

archivedWork is closed; lineage remains readable but lifecycle changes are owner-controlled.

Lifecycle

create_business_case(...)Create a new Business Case.

Creates a Business Case owned by the authenticated user and returns BusinessCase.

  • name — required, 1–200 characters; globally unique case-insensitively. Example: "Customer churn".
  • description — optional plain-language scope. Example: "Predict voluntary churn for active customers.".
  • problem_type — defaults to custom. Allowed: binary_classification, multiclass_classification, regression, forecasting, clustering, anomaly_detection, custom.
  • status — defaults to draft. Allowed: draft, active, production, archived.
  • business_owner — optional accountable person or team label. Example: "Retention team".
  • primary_metric — optional metric name used to assess the solution. Example: "roc_auc".
  • target_column — optional target-field name. Example: "churned".
  • business_goal — optional outcome the initiative should achieve. Example: "Reduce voluntary churn.".
  • success_criteria — optional measurable acceptance criterion. Example: "ROC-AUC >= 0.82".
case = client.create_business_case(name="Customer churn", problem_type="binary_classification")
ensure_business_case(...)Find by name or create safely.

Reuses a visible Business Case with the requested name; otherwise creates it. Handles concurrent creation conflicts safely.

  • name — required, 1–200-character globally unique name; it is used for the lookup and creation.
  • description — optional creation description when the case is absent.
  • problem_type — optional creation value; allowed values are the seven problem_type values listed for create_business_case.
  • status — optional creation value; allowed: draft, active, production, archived.
  • business_owner — optional owner/team label when creating the case.
  • primary_metric — optional metric name when creating the case.
  • target_column — optional target-field name when creating the case.
  • business_goal — optional intended business outcome when creating the case.
  • success_criteria — optional measurable acceptance criterion when creating the case.
case, created = client.ensure_business_case(name="Customer churn", primary_metric="roc_auc")
get_business_case(business_case)Get one case by ID.

Fetches full Business Case details. Passing an existing BusinessCase returns it without a request.

  • business_case — Business Case ID or BusinessCase.
case = client.get_business_case("bc_123")
get_business_case_by_name(name)Get one visible case by name.

Resolves the globally unique Business Case name visible to the authenticated user.

  • name — exact Business Case name.
case = client.get_business_case_by_name("Customer churn")
business_case_by_name(name)Compatibility alias for name lookup.

Legacy-compatible alias of get_business_case_by_name.

  • name — exact Business Case name.
case = client.business_case_by_name("Customer churn")
update_business_case(business_case, **changes)Change selected lifecycle fields.

Preserves unspecified fields required by the REST contract and returns the updated case.

  • business_case — Business Case ID or BusinessCase.
  • **changes — any of name, description, problem_type, status, business_owner, primary_metric, target_column, business_goal, success_criteria.
case = client.update_business_case(case, status="active", primary_metric="roc_auc")
archive_business_case(business_case)Archive while retaining lineage.

Sets the lifecycle status to archived; it does not delete any governed objects.

  • business_case — Business Case ID or BusinessCase.
archived = client.archive_business_case(case)
activate_business_case(business_case)Return a case to active status.

Sets the lifecycle status to active.

  • business_case — Business Case ID or BusinessCase.
case = client.activate_business_case(case)
transfer_business_case_ownership(...)Audited ownership transfer.

Transfers ownership through the platform’s audited endpoint.

  • business_case — Business Case ID or BusinessCase.
  • new_owner_id — ID of an active user.
  • reason — optional audit explanation.
case = client.transfer_business_case_ownership(case, new_owner_id="user_42", reason="Team handover")

incoming = client.page_business_case_access_requests(box="incoming")
approve_business_case_access_request(...)Approve and grant a role atomically.

Approves one pending request through the platform authorization workflow.

  • request_id — ID of a pending access request.
  • access_role — allowed: report_viewer, reader, contributor, manager. owner is rejected and the selected role cannot exceed the approver’s role.
  • decision_note — optional recorded explanation, up to 2,000 characters.
client.approve_business_case_access_request(request.id, access_role="reader")
reject_business_case_access_request(...)Reject one pending request.

Records a rejection without granting Business Case access.

  • request_id — ID of a pending access request.
  • decision_note — optional recorded explanation, up to 2,000 characters.
client.reject_business_case_access_request(request.id, decision_note="Not required")

Data attachments

attach_dataset(...)Bind an immutable dataset version to a case.

Creates a role-specific attachment and returns BusinessCaseDataAttachment.

  • business_case — Business Case ID or BusinessCase.
  • dataset — immutable dataset ID or Dataset.
  • role — required data role, e.g. training.
  • context_note, primary_key_column, target_column — optional context.
attachment = client.attach_dataset(case, dataset, role="training")
page_business_case_attachments(...)Search attachments in one bounded page.

Returns mapped data with lightweight latest-version metadata.

  • business_case — Business Case ID or BusinessCase.
  • limit — number of entries, integer from 1 to 100; default 30.
  • offset — zero-based number of entries to skip, integer ≥ 0; default 0.
  • search — optional text filter; default "".
  • role — optional exact data role: source, training, validation, test, scoring_input, scoring_output, monitoring_input, monitoring_actuals, reference.
  • pipeline_id — optional pipeline ID filter; default "".
  • pipeline_type — optional pipeline-type filter; default "".
  • uploaded_only — boolean; True keeps uploaded source data only, default False.
  • deleted_only — boolean; True keeps deleted data only, default False.
page = client.page_business_case_attachments(case, role="training")
list_business_case_attachments(case_or_id)Legacy full attachment list.

Compatibility method returning all attachments. Prefer the page or iterator methods for scalable workflows.

  • case_or_id — Business Case ID or BusinessCase.
attachments = client.list_business_case_attachments(case)
iter_business_case_attachments(...)Explicitly traverse selected attachment pages.

Yields all matching attachments without an unbounded API response.

  • business_case — Business Case ID or BusinessCase.
  • search — optional text filter; default "".
  • role — optional exact data role from the nine values listed for page_business_case_attachments.
  • page_size — fetch size, integer from 1 to 100; default 100.
for attachment in client.iter_business_case_attachments(case, role="training"):
    print(attachment.data_asset_id)
get_business_case_attachment(...)Get one attachment by ID.

Resolves an attachment through bounded pages until a direct REST detail endpoint is available.

  • case_or_id — Business Case ID or BusinessCase.
  • attachment_id — attachment ID.
attachment = client.get_business_case_attachment(case, "attachment_123")
update_business_case_attachment(...)Update the attachment context.

Changes role/context fields without changing the immutable data version.

  • case_or_id — Business Case ID or BusinessCase.
  • attachment_or_id — attachment ID or typed attachment.
  • **changes — role, context_note, primary_key_column, target_column.
attachment = client.update_business_case_attachment(case, attachment, context_note="Validated")
find_attachment(...)Resolve one dataset attachment.

Finds exactly one binding by immutable dataset ID and, optionally, role.

  • case_or_id — Business Case ID or BusinessCase.
  • dataset_or_id — immutable dataset ID or Dataset.
  • role — optional exact role filter.
attachment = client.find_attachment(case, dataset, role="training")
detach_dataset(...)Remove only the Business Case link.

Detaches the dataset; the dataset version and its lineage remain available.

  • case_or_id — Business Case ID or BusinessCase.
  • attachment_or_id — attachment ID or typed attachment.
client.detach_dataset(case, attachment)

Errors

HTTP failures map to AuthenticationError (401), AuthorizationError (403), ResourceNotFoundError (404), and ConflictError (409). Name and attachment resolvers can also raise ResourceAmbiguousError.
