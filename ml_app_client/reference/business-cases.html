Business Cases

The governed workspace for an ML initiative: its business purpose, access boundary, and lineage anchor. Dataset-to-Business-Case mappings are intentionally owned only by Dataset Attachments.

Normal lifecycle is draft, active or production, then archived. Archiving preserves lineage; permanent cascade deletion is root-only REST maintenance and is intentionally not exposed by this client.

What is a Business Case?

A Business Case supplies the business definition required to interpret data, pipelines, models, scoring, serving, and monitoring. Typed objects retain mapping compatibility: both case.id and case["id"] work.

Business context

Stores goal, owner, problem type, target, success criteria, and primary metric.

Access boundary

Controls governed resource access; administrators have an audited global bypass.

Lineage anchor

Connects immutable data, runs, models, reports, services, and monitoring results.

Dedicated data mappings

Role-specific Dataset bindings use the separate Dataset Attachments module.

Lifecycle

create_business_case(...)Create a Business Case owned by the authenticated caller.

Returns BusinessCase. Name is globally unique case-insensitively.

  • name — required, 1 to 200 characters.
  • description — optional plain-language scope; default "".
  • problem_type — accepted value; default custom.
  • status — accepted lifecycle value; default draft.
  • business_owner, primary_metric, target_column — optional business definition fields.
  • business_goal, success_criteria — optional outcome and measurable acceptance criterion.
case = client.create_business_case(name="Customer churn", problem_type="binary_classification", primary_metric="roc_auc")
get_business_case(...)Read one Business Case by ID.

Returns the typed object, or returns an already typed instance unchanged.

  • business_case — required Business Case ID or BusinessCase.
case = client.get_business_case("business-case-id")
get_business_case_by_name(...)Resolve one visible Business Case by exact name.

Searches bounded API pages, never an unbounded local list.

  • name — required exact visible name.
case = client.get_business_case_by_name("Customer churn")
update_business_case(...)Update editable definition fields.

The client fetches current state and supplies REST-required fields omitted from changes.

  • business_case — required Business Case ID or BusinessCase.
  • **changes — any of name, description, problem_type, status, business_owner, primary_metric, target_column, business_goal, success_criteria.
case = client.update_business_case(case, status="active")
archive_business_case(...)Archive without deleting governed lineage.

activate_business_case is the matching helper that returns a Business Case to active.

  • business_case — required Business Case ID or BusinessCase.
archived = client.archive_business_case(case)
transfer_business_case_ownership(...)Transfer ownership through the auditable endpoint.

Returns the updated Business Case.

  • business_case — required Business Case ID or BusinessCase.
  • new_owner_id — required target user ID.
  • reason — optional recorded explanation.
case = client.transfer_business_case_ownership(case, new_owner_id="user-id", reason="Team handover")

Catalog and idempotency

page_business_cases(...)Search visible Business Cases in a bounded page.

Returns CatalogPage[BusinessCase] with exact filtered total.

  • limit — requested entries, from 1 to 100; default 30.
  • offset — zero-based matching entries to skip; default 0.
  • search — optional text filter; default "".
  • manageable_only — when true, restricts to cases the caller can manage.
page = client.page_business_cases(search="churn", manageable_only=True)
iter_business_cases(...)Explicitly traverse every selected catalog page.

Use only when the full selected result range is intended.

  • search, manageable_only — optional page filters.
  • page_size — requested entries per API page, from 1 to 100; default 100.
for case in client.iter_business_cases(search="churn"): print(case.name)
ensure_business_case(...)Reuse an accessible name or create the case safely.

On an inaccessible global-name conflict, raises AuthorizationError rather than creating a duplicate.

  • **definition — same supported fields as create_business_case; name is required.
case, created = client.ensure_business_case(name="Customer churn", problem_type="binary_classification")

Errors

HTTP failures map to AuthenticationError (401), AuthorizationError (403), ResourceNotFoundError (404), and ConflictError (409). Exact-name resolution can also raise ResourceAmbiguousError.
